# verify（コミット前の確認と記録）

コミットの前に、このリポジトリの確認を実行して結果を確かめる。通ったら、その時点の状態を verify-layer の台帳に記録する。台帳は「確認したときの状態」と「コミットした状態」を比べるので、記録は確認が終わった直後にとる。

## 1. 確認の手順を決める

このリポジトリでの確認の手順は 1 か所にまとめてある。次の順に探し、最初に見つかったものに従う。

1. `.claude/skills/verify/SKILL.md`（Claude Code の `/verify` が記録した、このリポジトリの確認手順）。書かれたコマンドと合否の基準をそのまま使う。Claude と Codex で同じ確認になるよう、手順をこのスキルに書き写したり、別の手順に置き換えたりしない
2. 見つからなければ、README・CONTRIBUTING・`package.json` の scripts・Makefile・CI の設定（`.github/workflows/` など）から、今回の変更に関係する確認を選ぶ。選んだコマンドと、選んだ理由を報告に書く

`.claude/skills/verify/` には書き込まない。そこは Claude の `/verify` が自分の記録として使う場所で、書き換えると Claude 側の確認が変わってしまう。

## 2. 確認を実行する

- 手順のコマンドを実行し、出力から合否を判断する。終了コードだけでなく、手順に書かれた合格の条件（特定の出力など）も見る
- 失敗したら原因を直し、確認を最初からやり直す。直すためにファイルを変えたら、それより前の「通った」はもう使えない
- 実行できない確認（認証が要る、環境がない、など）は、飛ばした理由を報告に書く。通ったことにはしない

## 3. 結果を報告する

利用者に、実行したコマンド・合否・飛ばしたものとその理由を短く伝える。全部が通っていなければ、ここで止めてコミットしない。

## 4. 記録する（最後の手順）

確認がすべて通ったら、コミットの前に、AGENTS.md にある verify-layer の行（`mark verify --agent codex` を含む行）のコマンドを、そのまま実行する。`vl.js` の場所は端末ごとに違うので、このスキルには書いていない。AGENTS.md にその行がなければ、この端末には verify-layer が入っていないので、この手順は飛ばしてよい。

- 記録は作業を止めない。記録に失敗したと表示されても、そのことを報告に書いて先に進んでよい
- 出力に確認項目（`[verify-layer] 次の確認項目が…`）が出たら、それも確かめてからコミットする。確かめるためにファイルを変えたら、手順 2 からやり直して、もう一度記録する
- 出力に警告（チェック自体を触っている、など）が出たら、利用者に内容を見せて確認を求める
- 記録のあとにファイルを変えたら、確認と記録をやり直す
